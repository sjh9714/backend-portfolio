### AI 그림일기 — 이 앱의 핵심 기능 (2026-08-06 사용자 확인)

사용자 원문: *"앱 기획에서 자신의 하루를 ai 생성 이미지로 나타내고 계속해서 그림체가 달라지며
그걸 다이어리에 저장한다는 거야."*

**장식이 아니라 제품 기능이다.** 처음에 이걸 장식으로 보고 "AI 그래픽 금지 규칙과 충돌한다"고
잘못 보고했다. 구현 근거:

- `src/data/selectors.ts:226` `getDayDominant(dateKey)` — 그날 지출을 소비/저축/투자로 합산해
  가장 큰 것을 그날의 주인공으로 판정
- `src/data/diary.ts` `DIARY_ART` — 1~22일 그림일기. 주석에 그림체 7종이 날짜별로 배분돼 있다:
  팝아트(6·7·21) · 민트 포스터(2·5·9·16) · 리소그래프(4·8·14) · 종이 콜라주(1·13·17) ·
  자수(3·12·19) · 클레이 3D(11·15·18·22) · 로우폴리 3D(10·20)
- `src/features/diary/DiaryPage.tsx` · `DayCardsOverlay.tsx` — 화면 연결

현재는 정적 파일 22장. 백엔드 재구현에서 **실제 생성까지** 만든다 (사용자 확정).

## 백엔드 현황 — 왜 다시 만드는가

`finmate-api`는 Java 21 · Spring Boot, 165파일에 통합 테스트도 있다. 그런데:

```
finmate-api 도메인   quests · records · goals · rewards · mate · auth · data · documentation
finmate-app 기능     diary · feed · insights · mate · missions · my · onboarding
```

**IA가 다르다.** `finmate-api`는 "vNext"라는 별도 제품 정의로 설계됐고,
`finmate-app`은 백엔드 없이 목으로 돌아간다. **둘은 한 번도 연결된 적이 없다.**

커밋도 3일(07-13~07-15) 만에 `codex/` 브랜치로 쌓였다 —
`68a2f0e feat: integrate locked synthetic data release` 한 커밋이 **87파일 5,624줄**이다.

그래서 재구현의 정의: **`finmate-app/src/data/`를 계약으로 삼아 프론트가 실제로 붙는 백엔드를 만든다.**
