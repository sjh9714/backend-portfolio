직전 버전은 훅→기→승→전→결의 서술체였고, 그 형식이 **동기·발견 경위·소감**을 요구했다.

- "이 규칙을 외우는 대신 어느 조건에서 무엇이 무너지는지 직접 보고 싶었습니다" (동기)
- "검증받아야 할 대상이 아니라 이 도구가 먼저 버그를 잡았습니다" (발견 경위)

## 지금 남아 있는 확인 항목

### 1. 낮은 위험 — 근거는 있으나 출처 문서가 자기 부인 중

`n-plus-one` 케이스의 아래 두 문장은 realtime-chat `PERF_RESULT.md`에서 왔다.
그 문서는 **성능 수치**에 대해 자기 부인 배너를 달고 있지만, 이 둘은 벤치마크가 아니라 구현 사실이다.

- "응답에 실제로 필요한 필드가 6개뿐임을 확인하고 Entity 로드 자체를 제거"
  → `ChatRoomListResponse`의 필드 수로 확인 가능
- "Redis Cache Aside(TTL 5분)를 얹되 무효화 범위를 이벤트별로 축소"
  → 캐시 설정 코드로 확인 가능

- [ ] 코드와 일치하는지 한 번 확인 (불일치하면 문장을 빼면 됨)

### 2. 표기 확인

- [ ] eta 참여 인력을 `"개발 4명(본인 BE 전담) / 기획·리서치 3명"`으로 적었다.
      README의 "프로덕트 개발 4 · 기획·리서치 3"에서 도출한 것이라 개발 4명의 내부 구성(FE 몇 명)은 추정하지 않았다.
      실제 구성과 다르면 알려줄 것.
- [ ] billing-gateway는 저장소에 프레임워크 버전이 명시돼 있지 않아 `Java 21` 외에는 버전을 적지 않았다.
      자료는 버전 명시를 권하므로, 아는 버전이 있으면 채우는 편이 좋다.

### 3. 여전히 유효한 대기 항목

- [ ] **realtime-chat 재측정.** 절차와 승격 체크리스트는 `docs/facts/realtime-chat.md`에 있다.
      완료되면 `n-plus-one` 케이스의 `결과`에 실제 개선 수치를 추가할 수 있다.
- [ ] 학력·자격증 정보가 확인되지 않아 이력서에 없다.
