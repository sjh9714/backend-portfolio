# 확인이 필요한 문장

작성일: 2026-08-05

카피는 `docs/facts/*.md`의 검증된 사실 위에 썼습니다. 그런데 **사실만으로는 서사가 되지 않아서**,
동기("왜 시작했나")·경위("어떤 순서로 알게 됐나")·소감("무엇을 배웠나")은 제가 채웠습니다.
저장소 코드와 문서로는 이걸 확인할 방법이 없습니다 — 본인만 압니다.

아래 문장이 **실제 기억과 다르면 알려주세요. 고치겠습니다.**
사실관계(수치·구현·테스트)는 전부 대장에 근거가 있으니 그쪽은 확인하지 않으셔도 됩니다.

## concert-booking

**`narrative.attempt`**
> "교과서에는 규칙이 있습니다. 충돌이 잦으면 비관적 락, 드물면 낙관적 락.
> **이 규칙을 외우는 대신 어느 조건에서 무엇이 무너지는지 직접 보고 싶었습니다.**"

- [ ] 락 세 개를 구현한 동기가 정말 "규칙이 어디서 깨지는지 보고 싶어서"였나?
      아니면 단순히 세 방식을 다 익혀 보려던 것이었나?

**`narrative.lesson`**
> "규칙을 아는 것과 그 규칙이 어디서 깨지는지 아는 것은 다른 일이었습니다.
> 뒤쪽은 직접 재봐야만 알 수 있었습니다."

- [ ] 이 결론이 본인 생각과 맞나?

## realtime-chat

**`narrative.attempt`** — 마지막 문장
> "여기까지는 설계입니다. **문제는 이게 정말 작동하는지 어떻게 아느냐였습니다.**"

- [ ] 검산 도구를 만든 계기가 맞나?

**`narrative.twist.finding`** — ⚠️ 가장 확인이 필요한 문장
> "그런데 **검증받아야 할 대상이 아니라 이 도구가 먼저 버그를 잡았습니다.**
> Redis 패턴 구독에서 수신 채널 이름을 그대로 전송 목적지로 쓰고 있었고,
> 그래서 메시지가 엉뚱한 방까지 브로드캐스트되고 있었습니다."

- 버그와 수정 자체는 저장소에서 확인됨 (`RedisPubSubServiceTest`의
  `onMessageUsesEventRoomIdWhenPatternTopicProvidesPatternChannel`)
- [ ] **하지만 "receiver matrix 도구를 만들다가 이 버그를 발견했다"는 순서가 맞나?**
      다른 경로로 발견했다면 이 문단 전체를 다시 써야 합니다. 서사의 절정이라 특히 중요합니다.

**`narrative.lesson`**
> "검산 도구를 만들면 부산물이 생깁니다 — 이 프로젝트에서는 그게 실제 버그였습니다."

- [ ] 위 순서가 틀리면 이 문장도 함께 빠집니다.

## ai-usage-billing-gateway

**`narrative.attempt`**
> "**그래서 기능 목록부터 만들지 않았습니다.** 대신 돈이 틀어질 수 있는 경계를
> **먼저** 네 개로 좁혔습니다 — 중복 계량, 결제 webhook 재전달, 원장 불일치, 테넌트 간 데이터 누출."

- 네 경계에 대한 방어와 검증이 존재하는 것은 저장소에서 확인됨
- [ ] **하지만 "경계를 먼저 정의하고 시작했다"는 순서가 맞나?**
      만들면서 하나씩 발견한 것이라면 그렇게 쓰는 편이 더 정확하고, 사실 더 설득력 있습니다.

**`narrative.lesson`**
> "돈을 다루는 코드에서는 '아마 괜찮을 것'이 통하지 않습니다.
> 그래서 이 프로젝트에서 배운 것은 과금 로직이 아니라,
> 주장할 수 있는 것과 없는 것을 나누는 습관이었습니다."

- [ ] 이 소감이 본인 것인가?

## eta

**`narrative.lesson`**
> "백엔드가 내리는 설계 결정 중에는 무엇을 응답에 넣을지뿐 아니라
> **무엇을 지어내지 않을지도 있다는 걸 여기서 배웠습니다.**"

- UNKNOWN을 일급 상태로 둔 것은 README에서 확인됨
- [ ] **하지만 그 결정이 본인 것이었나, 팀 결정이었나?**
      백엔드 전담이셨으니 API 계약은 본인 몫이었을 것 같지만, 확인이 필요합니다.
      팀 결정이었다면 "팀이 정한 원칙을 API 계약으로 옮겼다"로 바꾸는 게 정확합니다.
