# 다이어그램 작성 규칙

『개발자를 위한 이력서 포트폴리오 완벽 가이드 2』 2-3장을 그대로 따른다.

- **앱 화면 캡처를 쓰지 않는다.** 백엔드는 기능 화면이 아니라 구조와 흐름을 보여야 한다
- **아이콘을 쓰지 않는다.** Docker 고래, Spring 나뭇잎 같은 이미지는 가독성을 떨어뜨린다
- **사각형 위주로 구성하고 각 요소를 텍스트로 명확히 표기**한다
- 시퀀스 다이어그램 · 데이터 흐름 · 변경 전후 아키텍처 · 테스트 결과가 적합한 소재다
- **모든 문제 해결 항목에 그림이 하나씩 붙는다.** 그림으로 표현할 수 없는 사례는 애초에 넣지 않는다

## 공통 토큰

화이트 테마에 맞춘 값이며 `src/app/globals.css`와 동기화한다.

| 용도 | 값 |
| --- | --- |
| 배경 | `#ffffff` |
| 보조 면 | `#f0f1fa` |
| 선·글자 | `#0a0b0d` |
| 보조 글자 | `#5a5f6e` |
| 경계선(약) | `#dcdee8` |
| 액센트 | `#0016ec` |

viewBox는 `0 0 880 420`으로 통일한다 (`src/components/case-study.tsx`가 880×420으로 렌더).
